How it works

Your machine dials out, so nothing has to reach in

The client opens one outbound connection to a server you run. Public traffic terminates TLS at the edge and rides the tunnel back to your localhost as raw bytes.

No HTTP parsing or multiplexing on the tunnel, which keeps the whole thing small enough to read and the path fast. HTTP and WebSocket both just work.

Why viaduct

Minimal on purpose

  • Free and open source

    MIT licensed, no quotas, no accounts. Run it locally or self-host the server.

  • One command

    viaduct http 4000 and you have a public HTTPS URL. The client dials out, so no inbound ports.

  • HTTP and WebSocket

    Raw byte piping means live reload, dev servers, and real-time sockets pass straight through.

  • Self-hosted, no accounts

    One droplet, your domain, your data. Restrict access at the firewall instead of behind a login.

  • Automatic HTTPS

    Caddy fetches and renews wildcard certificates over DNS-01. Public TLS with nothing to configure.

  • Small enough to read

    The client and server are plain asyncio and the standard library. If it surprises you, read why.

Self-hosting

Easiest on a DigitalOcean droplet

The provisioner is built for DigitalOcean. One Ubuntu droplet and one script sets up Caddy, wildcard TLS, systemd, and the firewall for you. A 1 GB droplet is plenty, and the same script rehearses locally first.

Install

Up and running in two commands

Requires Python 3.11 or newer. pipx keeps the CLI isolated and on your PATH.

$ pipx install git+https://github.com/webmull/viaduct
$ viaduct http 4000

Full usage, self-hosting, and the design notes live in the README on GitHub.
